# Backup UX Design

**Date:** 2026-05-19

**Problem**

当前备份流程虽然已经支持“合并并覆盖”，但用户侧感知仍然偏弱：
- 选择非空目标目录时，确认文案没有明确说明“会合并已有目录、会覆盖同名文件、未冲突文件会保留”。
- 选定目标目录后，状态区只显示路径，没有告诉用户本次备份的处理策略。
- 备份完成、取消、失败时，文案较笼统，用户不容易快速判断实际结果。
- 备份中状态信息已有基础进度，但整体流程反馈还不够完整，缺少“准备中 / 复制中 / 完成 / 取消 / 失败”的统一表达。

**Goals**

- 明确告知“合并并覆盖”的行为边界，避免用户误解。
- 在选择目标目录、开始备份、进行中、完成后都提供一致的流程反馈。
- 保持当前单一路径的备份策略，不引入额外分支或复杂设置。
- 保留危险冲突拦截：如果目标位置存在同名文件而不是目录，继续阻止备份。

**Non-Goals**

- 本轮不新增“跳过/保留两份/版本化”等可选冲突策略。
- 本轮不改动备份核心算法以外的大块 UI 布局。
- 本轮不引入新的设置页或高级选项。

**Interaction Design**

- 用户选择空目录时，直接接受，不弹额外确认。
- 用户选择非空目录时，弹出明确确认框：
  - 说明目标目录非空。
  - 说明本次将按“合并并覆盖”方式备份。
  - 说明已有同名文件会被覆盖，其他文件会保留。
- 用户确认后，状态区立即显示：
  - 目标路径。
  - 备份方式：合并已有目录，覆盖同名文件。
- 备份开始后，状态区统一进入“正在准备备份...”和“正在备份：xxx”的流程表达。

**Feedback Design**

- 选定目标目录后：
  - 第一行显示 `将备份到：<path>`。
  - 第二行显示 `备份方式：合并已有目录，覆盖同名文件`。
- 备份进行中：
  - 继续显示当前文件、文件进度、已处理容量、速度。
  - 当总量未知时，显示“进行中”而不是空洞提示。
- 备份成功：
  - 状态区显示 `备份已完成（合并并覆盖）`。
  - 成功消息框显示 `备份已完成：已合并已有目录，并覆盖同名文件。`
- 备份取消：
  - 状态区显示 `备份已取消，已保留已复制内容`。
- 备份失败：
  - 状态区显示 `备份失败：<message>`。
  - 继续通过现有错误通道弹出错误框。

**Implementation Approach**

- 在 `views/backup_dialog.py` 中集中收敛备份文案：
  - 提取目标目录说明文案 helper。
  - 提取非空目录确认提示文案 helper。
  - 调整开始、进度、成功、取消、失败状态文案。
- 保持 `views/main_window.py` 的备份启动流程不变，只让对话框承载更明确的文案反馈。
- 保持 `services/file_scanner.py` 当前“合并并覆盖”实现，仅沿用“同名文件冲突时仍报错”的校验。
- 通过 UI 测试锁定文案与按钮状态，避免后续回归。

  - 成功完成后状态文案与成功提示文案正确。
